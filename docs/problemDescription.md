# 全栈题目

## 用户痛点

很多 B站 / Youtube / 抖音 长视频没时间看，但用户需要：

- 快速掌握视频的关键事实、论点、逻辑链条、结论与可行动建议
- 以后可以用不同用途/风格再次生成内容（而不是一次性总结完就丢）

## 任务目标

做一个系统（形态不限：webapp/插件/CLI/桌面均可），输入一个无付费墙的 B站 / Youtube / 抖音 长视频 URL，产出并沉淀"可复用的知识资产"，并支持资产的增删改查、基于一份或多份资产进行多种输出生成与再利用。

## 必须包含的能力模块（但实现细节完全自定）

### 1）输入与资产化

- 输入：任意公开可访问的 B站 / Youtube / 抖音 长视频 URL

- 系统需要把该视频变成一个"资产"，后续可以再次被访问/复用/再生成（具体怎么组织、如何判断"复用"、如何更新，请往下阅读，留白全部留给你设计）

### 2）内容抽取

从视频中抽取你认为"足以支撑后续生成"的信息（必须以某种形式包含视觉内容，不能纯音频和转写/字幕）。例如（但不限）：

- metadata（标题/简介/UP/标签等）
- 音频/字幕/转写文本
- 关键帧/截图/片段
- 任何你认为必要的结构化信息（例如：论点列表、时间线、概念表、因果链等）

抽什么、抽多少、按什么策略抽，各类信息先抽再存还是先存再抽，都是你设计的一部分。

### 3）记忆化存储（Memory/RAG/DB 任意）

把"抽取结果 + 结构化信息 + 引用/溯源能力"写入一个存储层，以支持：

- 回看某个视频的资产
- 基于一个或多个视频进行查询/生成

（可以选开源 memory 框架，也可以手搓；选型与数据结构是考察点。）

### 4）输出与交互层

对于任意选定模态，用户还可以通过自然语言 prompt 指定侧重点（例如：偏事实、偏观点、偏步骤、偏争议、偏复盘）。

用户可以指定一个或多个视频资产作为内容来源。

至少实现 2 种输出模态，你可以从下面任选（也可以自创）：

- **图文并茂总结**（必选，要求有截图/关键帧做配图）
- 小红书图文（标题、分段、tag、风格化表达）
- 理解测验题集：输出一套题来检验观众是否真正理解视频
- 脑图/结构图：把视频知识结构化成可视化（形式自定：Markdown 层级、Mermaid、JSON、图片导出或你觉得合适的任意）

**思考方向（非强制，但会纳入评分）**：

- 用户从输入URL到得到输出，经历了哪些步骤？每个步骤的体验是否流畅？
- 处理等待时用户能看到什么？是否有机会中断或调整？
- 生成结果后用户能否编辑、修正、重新生成？
- "可复用"在你的系统里具体指什么？用户如何复用已有资产？

## 交付要求

### 核心交付物

- 一个 repo + README（能让评审在本地跑起来/看到效果，形式自选）
- Demo（录屏或可访问链接均可）
- 一页简短说明（可写在 README 里）：
  - 你的核心取舍：抽取策略、memory 结构、输出抽象、交互设计、你砍掉了什么
  - 失败/不确定性处理：缺字幕、下载失败、模型不稳定等怎么降级
  - 如果再给你 1 周，你会怎么迭代

### 部署与文档要求

**目标：用户从拿到作品到完成一次完整操作，流程越简单越好。**

| 评分项 | 说明 |
|--------|------|
| **启动命令数** | 从 clone 到看到界面，理想情况下不超过 2-3 条命令 |
| **文档清晰度** | README 需包含：前置条件、启动步骤、示例URL、预期输出 |
| **前置条件** | 明确列出所需环境（Node/Python/数据库等），避免用户踩坑 |
| **错误提示** | 启动失败时有明确的错误信息和解决建议，而非让用户猜 |
| **一键体验** | 最好提供 Docker/docker-compose 一键启动，或提供可直接访问的在线 Demo |

**减分项**：

- 需要用户手动配置 3 个以上环境变量才能启动
- 文档缺失或步骤描述模糊（如"参考XX文档"却不给链接）
- 启动后还需要额外操作才能看到效果（如先手动跑脚本生成数据）
- 无法在 10 分钟内完成首次操作闭环

## 我们希望考察什么？

### 产品感

是否有"用户中心"思维：

- 输出是否"真的有用"？
- 结构是否抓住关键点？
- 用户旅程是否完整？（从输入到输出，每一步是否有明确的反馈和引导）

### 工程能力

交付是否可运行、结构是否清晰、是否可扩展。

### 信息检索和快速学习

可参考项目、可用工具、API、debug 等等。

### 交互设计意识

- 操作效率：从URL到输出的路径是否简洁？
- 反馈及时性：关键操作是否有即时反馈？
- 容错性：出错后用户能否恢复，还是需要从头来过？

（不要求完美的交互设计，但需要体现出你思考过"用户怎么用"这个问题）

### 节奏感

开发规划/边想边做的方法论、迭代根据、在规定时间内你完成了多少次有效迭代（你怎么定义）、每次迭代闭环的"反馈→改动→效果"链条是什么。

### 新工具灵敏度

选型与上手是否高效、如何取舍。

### 使用 AI 开发能力

能否充分借助 AI 在规定时间内完成远超手搓规模的工程。

### 承压与取舍

是否形成闭环、是否能在复杂度里做正确删减、时间规划和取舍。
